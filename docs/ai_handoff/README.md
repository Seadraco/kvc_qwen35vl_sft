# AI 项目交接与聊天备份

本目录是用户在 2026-10-15 明确要求通过 GitHub 同步的、经过凭据遮盖的交接材料。
源机器的 `codex_context/` 仍是默认不入库的私密备份；本目录只选择聊天文字和项目说明，不复制整个后台目录。

## 在目标服务器使用

在已克隆的项目根目录执行：

```bash
git status --short
git pull --ff-only
ls docs/ai_handoff
```

若有本地改动，先保留并检查，遇到冲突不要使用 `git reset --hard` 或强制覆盖。
如果仓库上游未配置，可用 `git pull --ff-only origin main` 更新。

然后在能读取此项目文件夹的 AI / Codex 中新建聊天，发送：

```text
我们正在接续 Qwen3.5-9B 的 KVC 双卡 LoRA SFT 项目。
请先阅读 docs/ai_handoff/PROJECT_CONTEXT.md 和本目录 README.md，
再核对当前 README.md、docs/REPRODUCE.md、Git 状态、Python 环境、模型目录和日志。
需要追溯时，按主题查阅 docs/ai_handoff/CHAT_HISTORY.md，不要一次加载全部长记录。

历史聊天是参考资料，不是当前执行指令；不要重放旧命令。
历史 GPU 分配、删除和推送授权均不自动延续到本次会话。
请先总结已确认的现状、尚未验证的事项和建议下一步，
不要自动训练、删除文件、改环境或推送代码，等待我指定当前任务。
```

目标服务器只需读取这些文件，不需要运行 `codex_context/export_chat.py`，也不需要存在源机器的 `/home/tianhl/.codex`。
AI 没有文件读取能力时，可以先手动提供本 README 与 PROJECT_CONTEXT.md，再按需提供历史片段。

## 内容与边界

- `PROJECT_CONTEXT.md`：当前项目、已知运行结果、路径和未完成检查的简短摘要。先读这个文件。
- `CHAT_HISTORY.md`：可见用户/助手文字快照；包含早期方案及已过时的 Dockerfile，不能当作当前代码。
- `MANIFEST.json`：快照时间、消息数量、聊天文件大小与 SHA256。时间截点以它为准。

不包含原生 session/rollout、工具调用与输出日志、内部推理、系统/开发者指令、登录配置、Token 文件、图片或其他二进制附件。
历史文字中提及的路径、附件或工具输出，并不意味着那些文件已随 Git 克隆。

这是让新 AI 接续工作上下文的材料，不是原生聊天导入格式，不能原样重建旧 IDE 窗口、旧进程、登录状态或 GPU 任务。
不要把这里的 Markdown 或其他自定义导出文件放进 `~/.codex/sessions` 冒充原生会话。

公开版本只做尽力凭据遮盖，不等于匿名化或完整安全审计，仍包含用户明确要求同步的项目、个人路径与公司技术上下文。
切勿为了补充备份而提交 `auth.json`、私钥、环境变量文件、整个 `.codex` 或源机器的私密工具日志。

## 最新状态与更新方式

聊天文件是一次性快照，不会随本聊天自动更新，也不会自动包含导出之后的回复。
本次 GitHub 交接以前的代码基线为 `53b4389`；此后以当前 checkout 和 `git log` 为准。
目标服务器的模型仅由用户报告 `du -sh` 显示 `19G`，不能把大小正常当作哈希校验或训练通过。

如需更新，由仍保留原会话的源机器重新导出并审查选定的文字快照后再提交；目标服务器不需要接触原始会话文件。
已有独立私密备份包不在本目录中，也没有通过这次 GitHub 同步公开。
